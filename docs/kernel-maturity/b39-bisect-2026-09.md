## Verdict (one paragraph)

**No commit did — the premise is refuted.** The pinned repro refuses
identically at both ends of the requested range: at the filing commit
(`337e9999`, 2026-09-17) and on `origin/main` today (`fac12dd1`), the fuse
leg fails at `prop_boolean_invariants.rs:3480` with
`exact fuse succeeds: ExactOnlyUnattainable`, never reaching the mesh
oracle. It also refused at the original Sep-16 filing commit (`6a3fcb13`,
byte-identical repro construction) and at every sampled mainline commit
back to `e3a3382` (2026-08-31). Below the gate, raw GFA
(`remus_algo::gfa::boolean`) returns a degenerate open shell
(V=1, E=1, F=1, Euler=1), which the acceptance gate correctly rejects and
`ExactOnly` correctly declines to mesh-fallback — a **correct fail-closed**,
not a regression. The row's "watertight at 0.1, 254 boundary at 0.01/0.001"
narrative was never reproducible from the pinned repro on any tested
commit; it most likely came from the pre-minimization proptest case or a
dev-checkout state (hypothesis, not established). Formal `git bisect` was
inapplicable (it requires opposite outcomes at the range ends); a manual
binary search outward over 9 commits substitutes for it.

## 4. Mechanism on the current head (file:line)

Per the debugging-doctrine ladder (verify above AND below the gate):

- `remus_algo::gfa::boolean_with_context` returns `Ok` but the solid is a
  degenerate 1-face open shell (V=1, E=1, F=1, Euler=1, 1 boundary edge).
- The single-component acceptance gate in
  `crates/operations/src/boolean/mod.rs:1472-1479` (`euler_ok`, plus
  `open_shell_ok`, operand-representation, bounds, and
  `validate_boolean_result_with_tolerance`) rejects it; the multi-region
  gate at `mod.rs:1561-1578` cannot accept a 1-component result either.
- Control falls through to the mesh-fallback refusal point at
  `crates/operations/src/boolean/mod.rs:1679-1680`:
  `let FallbackPolicy::AllowApproximate { budget } = context.fallback
  else { return Err(OperationsError::ExactOnlyUnattainable); }`.
- Under `AllowApproximate` the same pair instead returns `Approximate`
  quality with 551 all-planar mesh faces, watertight at 0.1/0.01/0.001 of
  its own mesh — the mesh fallback, not the "handful of analytic faces +
  254 boundary" exact result the row describes. The row's numbers match
  neither the current exact path (refusal, no mesh) nor the current
  fallback path (551 faces, watertight).

Composition variants (move the torus instead of the cone; reversed
`Ry*T` order; operand swap) all refuse identically on this head, so the
cell refusal is robust, not a one-placement accident. (One out-of-scope
observation: the same shapes under `Rz(3π/2)` fuse `Exact` with 4 faces —
a trivially small overlap, not the reported crack; not pursued.)

## Fail-closed vs regression

**Fail-closed (correct refusal).** The gate declines a degenerate GFA
output that no validator could accept (open shell, Euler 1, and on Aug-31
additionally disconnected). There is no evidence on any tested commit
(2026-08-31 → today) that this cell ever produced a valid exact fuse the
new code now rejects; the roadmap would count such a rejection as progress
in any case. What is NOT established is where the row's "254 boundary"
reading came from — candidates are the pre-minimization proptest case
(shrinking aborted on this input, per the repro comment) or a
dev-checkout state; the pinned repro is unfaithful to that observation
from birth (a known failure mode — see the testing skill's
faithful-repro-first rule).

## Recommendation

1. Do not chase a mesh bug for the unit fuse: there is no mesh — the
   boolean correctly refuses. Rewrite the B39-unit narrative around the

   fix belongs in the algo intersection/assembly path (torus–cone section
   construction), not the tessellator.
2. If the original "254 boundary" exact result matters, re-derive a
   faithful repro from the Sep-16 slow-suite campaign logs/seeds
   (`B26CASE`/`B26SHRINK` lines, `prop_boolean_invariants`

   as it stands the pinned repro cannot demonstrate the claimed state.
3. Optionally bisect the oblique leg's Aug-31→Sep-10 refused→accepted

4. Keep the torus–cone generation exclusion until the GFA degeneracy is
   fixed; the exit gate ("all four ignored repros green") is unchanged.
